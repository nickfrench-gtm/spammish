# Privacy

Spammish's local desktop app and alternative browser worker process Gmail on your computer. It contacts Google's OAuth and Gmail endpoints to authorize access, refresh/revoke credentials, inspect the existing Inbox automatically after connection and new mail thereafter, create The Abyss label if missing, and move high-confidence matches by changing labels.

Subject, sender, and bounded message body content are processed in memory. Spammish does not store email bodies, load remote email images, fetch attachments, click message links, or transmit message content to an AI provider or maintainer. The desktop accounts file holds each connected email address, processing cursor, state, temporary message IDs/page checkpoints during the initial Inbox sweep, and a separate OS-encrypted refresh credential for each account. Temporary sweep IDs are dropped after completion. The initial sweep enumerates all Inbox IDs before inspection: this list grows with inbox size and may delay the first move. Feedback maps are retained until disconnect and have no fixed entry cap; this is not a claim that every state structure is bounded. It also retains a confirmed-move count, at most 50 recent confirmed-move records plus 50 recent kept-message decision records (message ID, time, score and feature codes; no subject or body), crash-recovery move intent, and account-specific hashed message/sender receipts and correction evidence. These hashes are salted per account; they are not anonymous to someone with access to that account file. Recent subjects/senders are fetched transiently from Gmail when you open or refresh the recent-decision review (the desktop loads it once when connected). Desktop metadata is not encrypted by the app; tokens use OS encryption. Protect your OS login and disk. Optional installation milestone sharing is described below; it is off until explicitly chosen. No mailbox analytics is included.

Candidate messages trigger bounded Gmail history searches for prior outbound communication, received mail, Spam labels and thread context. This is on-demand relationship hydration, not a copy of your entire mailbox or Contacts. URLs are inspected as text, never visited. Gmail Spam labels do not prove who marked the message spam. A move to The Abyss by another Gmail client is observable feedback, not proof of a particular user's action. Automatic Spammish moves do not become rejection evidence.

The loopback server uses the same engine. Its SQLite state, including tokens and metadata, is encrypted with the locally generated `.env` vault key. Anyone possessing both can decrypt it. Disconnect removes the selected saved account and feedback, retaining only its contribution to the aggregate counter without its account identity. SQLite/filesystem backups may retain previous encrypted state; disconnect is not forensic erasure.

The Gmail `gmail.modify` grant technically allows broader actions than Spammish performs. The published default code does not send, reply, trash, or delete mail. Classification is conservative but may make mistakes. Review The Abyss when needed and use Rescue or move a message back to Inbox using Gmail. This protects the exact sender and retracts its rejection evidence.

Pause stops the selected account. Stopping the local server stops all processing; the desktop tray also provides Pause all accounts and Quit. Disconnect clears only the selected account’s local credential and attempts revocation through Google. If offline revocation fails, remove the grant manually in your Google Account's third-party connections. Uninstalling alone may leave the OS account file or Google grant; disconnect first.

These statements describe the default source in this repository. Modified versions and forks can behave differently and are their operators' responsibility. Google's own services are governed by Google's privacy policy.

The application has no auto-update service. Installing dependencies/build runtimes contacts package registries and vendors; those services and Google process their own request metadata. Optional OS launch-at-login settings are used by the packaged desktop. The separate website has a distinct waitlist privacy notice. No claim is made that all network traffic remains on the device.

Desktop OAuth configuration can be bundled in a private local build or imported using the native file picker. Imported configuration stores only the client ID and client secret in a permissions-restricted local application file. It is not a Google password or mailbox access token and remains after account disconnect. It is not uploaded to Spammish.

## Optional desktop usage milestones

This source candidate adds an optional first-run choice and a **Usage privacy** control. The published 0.4.3 app remains telemetry-free until an approved follow-up release. The collector is not enabled in production by this change.

If you choose **Share usage milestones**, the desktop main process sends only a randomly generated installation UUID, one of six milestone names, app version and OS family to `https://spammish.fly.dev/api/milestones`. Milestones are app started, Gmail connected, first confirmed automatic Abyss move, successful background use after 7/30 elapsed days from consent after a move, and first Rescue. Each is recorded once per ID. They do not measure classification accuracy or identify people. No email/account data, message IDs, scores/evidence, credentials, hardware identifiers or local paths are sent. The alternative browser worker has no usage sharing.

The server adds a UTC receipt date, stores records privately for at most 90 days, and exposes no public analytics/report endpoint. There are no third-party analytics SDKs. The installation UUID is pseudonymous, not proof of anonymity: it links the milestones and the receiving host sees your network address. A transient salted address hash is used only in memory for abuse limiting. The code does not persist/log addresses or request bodies outside allowlisted milestone records; Fly.io may process its own network request metadata. Operator/provider backups require separate retention controls.

Choose **No thanks** to continue without sharing. Later use **Usage privacy → Turn sharing off & remove local ID** to abort queued work and remove the ID locally. Previously accepted events are not recalled; they expire within 90 days. Sharing again generates a new ID. Local milestone state is permissions-restricted, unencrypted, and separate from Gmail state. Disconnecting Gmail does not remove installation-level metrics; turn sharing off separately. Telemetry network or storage failure does not stop Gmail. See [exact semantics, exclusions and operator retention](docs/traction.md).
